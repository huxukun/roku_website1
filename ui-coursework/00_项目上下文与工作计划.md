## 2. 阶段一已完成内容（可直接复用的事实与结论）

### 2.1 研究对象事实（实地走查所得，均已截图存证）

- 系统：南京邮电大学教务管理系统，正式名「教学管理信息服务平台」，供应商**正方软件 V-9.0**，学生端 `jsdm=xs`。
- 访问路径：官网 `www.njupt.edu.cn` → 智慧校园 / 统一身份认证 → 教务系统；实际经 **WebVPN 隧道**（`vpn.njupt.edu.cn:8443`）访问。
- **核心痛点：登录孤岛** —— 官网/门户/教务三者登录状态不互通，进教务需二次登录；会话过期或新标签页打开会跳回独立登录页。
- 功能菜单树：**5 个一级菜单、23 个二级功能项**
  - 报名申请（考级项目报名、教学项目报名、校内课程替代申请、成绩课程性质修改申请）
  - 信息维护（学生个人信息维护、个人培养方案、自主学分确认）
  - 选课选教材（课程预选、自主选课、重修报名、教材预订）
  - 信息查询（个人信息、毕业审核结果核查、班级课表、个人课表、空闲教室、选课名单、学生成绩、考试信息、教材明细、实验课表、按周次课表）
  - 教学评价（学生评价、课程随堂评价）
- 页面路径使用拼音缩写（`kbcx` / `cjcx` / `kwgl` / `xspyfagl`），语义线索为零。

### 2.4 竞品分析结论

- **直接竞品**：正方同源教务系统（覆盖面广、问题普遍）、清华信息门户（门户整合 + 移动端与 PC 一致 + 单点登录）、浙大「学在浙大」（嵌入校园 App 工作台）。
- **间接竞品**：超级课程表、WakeUp 课程表、喜鹊儿、今日校园、完美校园。
- 结论：官方系统护城河是**数据权威性**，短板是**体验**；策略是「把官方做得比第三方更好用」，行业趋势 = 移动优先 + 门户整合 + 单点登录 + 场景化聚合。

### 2.5 SWOT 与组合策略（摘要）

- **S**：数据官方唯一、功能完整、强制使用、用户基数大（全日制在校生 3.3 万+）
- **W**：界面老旧、登录孤岛、会话过期、移动端差、首页无入口、命名晦涩、报错不友好、并发差
- **O**：移动优先改版、单点登录、一网通办、AI 问答/学业看板、并发优化、开放数据接口
- **T**：第三方 App 分流、选课崩溃舆情、被新系统替代、数据合规、多端不一致
- **SO**：以数据权威做移动优先一站式教务小程序，首页聚合高频入口
- **WO**：优先解决登录孤岛与移动端适配
- **ST**：开放数据接口 + 以官方为准，减少数据割裂
- **WT**：优化选课高峰并发与失败反馈，做舆情与合规预案

### 3.2 任务 B：三层流程图

**产出目录**：`03_设计稿/流程图/`

**产出物**：

```
03_设计稿/流程图/
├── 1-产品级流程图.md        （含 Mermaid 源码 + 导出 PNG）
├── 2-任务级流程图.md
├── 3-操作级流程图.md
├── 流程图说明.md            （三层之间的关系、编号规则、与页面的映射表）
└── 导出/                    （PNG/SVG，供作品集网站引用）
```

**三层定义（必须严格区分，这是本次作业的评审重点）**：

#### ① 产品级流程图（Product-level）

- **视角**：整个产品 / 跨角色端到端。
- **内容**：用户从「进入」到「完成目标」的宏观路径，含角色泳道（学生 / 系统 / 教务管理员）。只画主干，不画细枝末节。
- **必须覆盖**：登录（含单点登录与 WebVPN 退场）、首页分流、5 大核心任务出口、异常兜底（会话过期、选课失败）。
- **输出**：1 张泳道图，节点 ≤ 25 个。

#### ② 任务级流程图（Task-level）

- **视角**：单个任务的完整闭环。
- **数量**：5 张，对应 5 个核心任务。
  1. 查课表
  2. 查成绩
  3. 选课（含排队、冲突、失败重试）
  4. 考试查询
  5. 评教
- **每个任务必须包含**：入口 → 主路径 → 判断分支（成功/失败/无数据/冲突）→ 退出路径。
- **要求**：标注每步的**步数**，并在图下注明「改版前 X 步 → 改版后 Y 步」，与 G4 对齐。

#### ③ 操作级流程图（Operation-level）

- **视角**：单个页面上的具体操作与系统反馈。
- **数量**：至少 3 张（建议与 3 个最复杂任务对应）。
  1. 首页快捷卡片：点击 → 展开详情 → 返回
  2. 选课页：筛选 → 查看冲突 → 排队 → 成功/失败
  3. 会话过期：弹窗 → 一键重登 → 回到原页面（含原页面状态恢复）
- **要求**：每一步都要写清「用户动作 → 系统反馈 → 界面状态」，可直接映射到组件状态机。

**格式统一要求**：

- 用 **Mermaid** 写源码（便于版本管理和网站内嵌渲染），同时导出 PNG 到 `导出/`。
- 节点编号规范：`PL-xx`（产品级）/ `TL{任务号}-xx`（任务级）/ `OL{页面号}-xx`（操作级）。
- 每个流程图下方附「页面映射表」：流程节点 → 对应原型页面编号（P-01…P-06）。

### 3.3 任务 C：按流程图开发网站
